Browser OAuth (PKCE) — Pi ↔ ChatGPT Subscription

Authorization Code + PKCE flow with local callback server on port 1455
Objective
After this you'll understand how Pi authenticates with a ChatGPT Plus/Pro subscription using PKCE (Proof Key for Code Exchange) — a browser-based OAuth 2.0 flow that never exposes a client secret. Pi generates a one-time code challenge, the user logs in via browser, and a local HTTP server catches the redirect to exchange the authorization code for long-lived tokens.
Step 1
Generate PKCE & State
Pi creates a cryptographically random code_verifier (32 bytes, base64url-encoded). It SHA-256 hashes it to produce a code_challenge. A random state (16 hex bytes) prevents CSRF.

Key: The verifier stays in Pi; only the challenge is sent in the URL.
→
Step 2
Open Browser + Start Server
Pi starts a local HTTP server on 127.0.0.1:1455 to catch the redirect. It opens the browser to:

auth.openai.com/oauth/authorize
?response_type=code
&code_challenge=<challenge>
&code_challenge_method=S256
&state=<state>
&originator=pi
→
Step 3
User Authenticates
The user logs into their ChatGPT account on the OpenAI auth page. They grant the requested scopes: openid profile email offline_access.

Note: offline_access is what gives Pi a refresh token so the subscription stays active without re-login.
→
Step 4
Browser Redirects to Pi
OpenAI redirects the browser to:

http://localhost:1455/auth/callback
?code=<auth_code>
&state=<state>

Pi's HTTP server receives the request, validates state matches, and extracts the authorization_code. The browser sees a dark-themed success page.
→
Step 5
Exchange Code for Tokens
Pi POSTs to auth.openai.com/oauth/token:

grant_type=authorization_code
code=<auth_code>
code_verifier=<verifier>
redirect_uri=http://localhost:1455/...

OpenAI verifies the verifier hashes to the challenge → returns access_token + refresh_token.
