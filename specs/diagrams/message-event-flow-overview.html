Quark session model

Events are the source. Messages are the projection.

This view separates the durable event log from the working objects used by the app. User input and provider streams both become session events. Replay turns those events into message and part records, then adapters reshape them for the model and UI.

One Concrete Turn

The example below uses one user prompt with an image, one assistant tool round, one final answer, and one compaction summary. The same durable log feeds every later view.

User input path The user prompt and image do not come from a provider. Quark writes them directly through saveUserMessage().
Assistant path Provider stream events are interpreted by processStream(), then persisted as message, part, and message-end events.
Replay path MessageRow and PartRow are not disk records. They are memory projections built from the event log.
